# Skeleton: TCS Plugin

This file describes the proposed `claude-docs/` tree for a TCS plugin repository.
`plan` mode reads this skeleton and creates the pages listed below as empty
placeholder files. Each page entry states its purpose and the section structure
a first-time author should follow when writing the content.

---

## Proposed claude-docs/ tree

```
claude-docs/
├── README.md
├── installation.md
├── configuration.md
├── usage.md
├── troubleshooting.md
└── components-reference.md
```

---

## Page Descriptions

### claude-docs/README.md

**Purpose:** Top-level index that orients any reader landing in the `claude-docs/` directory.
Links to every other page so the tree is navigable from the root.

**Suggested section structure:**

- H2 `## Overview` — one paragraph describing what the plugin contributes to TCS
  (skills, agents, commands, hooks) and the workflows it supports.
- H2 `## Documentation map` — bulleted list of links to every page in `claude-docs/`:
  `installation.md`, `configuration.md`, `usage.md`, `troubleshooting.md`,
  `components-reference.md`.
- H2 `## Quick links` — optional; direct links to the fastest paths (e.g.
  "Install the plugin", "Available skills", "Configuration reference").

---

### claude-docs/installation.md

**Purpose:** Guides a TCS user through adding the plugin to their Claude Code
installation and verifying that the plugin's components are available.

**Suggested section structure:**

- H2 `## Prerequisites` — Claude Code version minimum; any peer plugins required.
- H2 `## Install via TCS marketplace` — the exact command or UI steps to install
  the plugin from the TCS marketplace.
- H2 `## Install from source` — cloning the repo, linking or copying to the correct
  Claude Code plugin path, restarting Claude Code to pick up the new plugin.
- H2 `## Verify the installation` — how to confirm the plugin loaded: check the
  `/` command menu for expected skill names; check that agents appear in the agent
  roster; confirm hooks are active.
- H2 `## Updating` — bump the version reference or `git pull` and restart;
  any migration steps between major versions.

### claude-docs/configuration.md

**Purpose:** Documents every user-configurable setting exposed by the plugin:
name, type, default value, and what it controls. Generated by `extract` mode
from the plugin's settings source. Authors should not edit this page by hand —
re-run `extract` when settings change.

**Suggested section structure:**

- H2 `## Plugin settings` — where settings live (e.g. `.claude/settings.json`,
  `plugin.json` stanza, or a dedicated settings file); how to open and edit them.
- H2 `## Settings reference` — Markdown table: `Name | Type | Default | Description`
  (one row per setting, produced by `extract` mode).
- H2 `## Defaults` — a complete minimal settings block the user can copy-paste to
  start from a known-good baseline.

---

### claude-docs/usage.md

**Purpose:** Shows a user how to invoke the plugin's components in practice,
covering the most common workflows across skills, agents, and commands.

**Suggested section structure:**

- H2 `## Invoking skills` — how to call each skill via `/skill-name` or the Skill
  tool; when to reach for each skill; example invocations.
- H2 `## Running agents` — how to dispatch agents; what context they need; how to
  interpret their output.
- H2 `## Using commands` — any slash commands contributed by the plugin; when to
  use a command vs a skill.
- H2 `## Common workflows` — 2–4 end-to-end examples combining multiple plugin
  components to accomplish a real task.

---

### claude-docs/troubleshooting.md

**Purpose:** Helps a user recover from the most common failure modes without reaching
the plugin author. Written from the user's symptom, not the author's debugging model.

**Suggested section structure:**

- H2 `## Common issues` — one H3 per issue: symptom as heading, cause, fix steps.
  At minimum: "Skill not appearing in `/` menu", "Agent errors on dispatch",
  "Hook not firing", "Settings not applied".
- H2 `## Plugin not loading` — steps to diagnose a plugin that is installed but
  whose components do not appear in Claude Code.
- H2 `## Filing a bug report` — what to include (Claude Code version, plugin version,
  exact invocation, full error text); where to file (GitHub Issues URL).

---

### claude-docs/components-reference.md

**Purpose:** Per-component reference for every component the plugin ships — skills,
agents, commands, and hooks. This is the per-component reference page covering
each component's trigger conditions, inputs, outputs, and constraints.

**Suggested section structure:**

- H2 `## Skills` — one H3 per skill:
  - Name and trigger phrases.
  - What it does (one sentence).
  - Inputs it expects (from `$ARGUMENTS` or conversation context).
  - Output format.
  - Constraints and known limitations.
- H2 `## Agents` — one H3 per agent:
  - Name and description.
  - When to dispatch (trigger conditions).
  - What it returns (output schema or format).
  - Tools it uses and why.
- H2 `## Commands` — one H3 per slash command:
  - Invocation syntax.
  - What it does and when to use it vs the equivalent skill.
- H2 `## Hooks` — one H3 per hook:
  - Event it listens on (PreToolUse, PostToolUse, Stop, etc.).
  - What it checks or enforces.
  - How to disable or override per session.
