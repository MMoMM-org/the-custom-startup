# Skeleton: Obsidian Plugin

This file describes the proposed `docs/` tree for an Obsidian plugin repository.
`plan` mode reads this skeleton and creates the pages listed below as empty
placeholder files. Each page entry states its purpose and the section structure
a first-time author should follow when writing the content.

---

## Proposed docs/ tree

```
docs/
├── README.md
├── installation.md
├── configuration.md
├── usage.md
├── troubleshooting.md
├── settings-reference.md
└── commands-reference.md
```

---

## Page Descriptions

### docs/README.md

**Purpose:** Top-level index that orients any reader landing in the `docs/` directory.
Links to every other page so the tree is navigable from the root.

**Suggested section structure:**

- H2 `## Overview` — one paragraph describing what the plugin does and who it is for.
- H2 `## Documentation map` — bulleted list of links to every page in `docs/`:
  `installation.md`, `configuration.md`, `usage.md`, `troubleshooting.md`,
  `settings-reference.md`, `commands-reference.md`.
- H2 `## Quick links` — optional; direct links to the most common tasks
  (e.g. "Install", "Configure", "First use").

---

### docs/installation.md

**Purpose:** Guides a first-time user through installing the plugin on their Obsidian
vault, verifying the installation succeeded, and knowing when to update.

**Suggested section structure:**

- H2 `## Prerequisites` — Obsidian minimum version; any other requirements.
- H2 `## Install from Community Plugins` — step-by-step: Settings → Community plugins →
  Browse → search → Install → Enable.
- H2 `## Install manually` — for pre-release or development builds: download `.zip`,
  copy to `.obsidian/plugins/<plugin-id>/`, reload Obsidian.
- H2 `## Verify the installation` — how to confirm the plugin loaded (Settings panel,
  command palette entry, ribbon icon).
- H2 `## Updating` — how to update via Community Plugins tab; any migration notes.

---

### docs/configuration.md

**Purpose:** Documents every user-configurable setting: name, type, default value,
and what it controls. Generated by `extract` mode; authors should not edit this
page by hand — re-run `extract` when settings change.

**Suggested section structure:**

- H2 `## How to open settings` — Settings → Community plugins → plugin name → gear icon.
- H2 `## Settings reference` — Markdown table: `Name | Type | Default | Description`
  (one row per setting, produced by `extract` mode).
- H2 `## Tips` — optional; non-obvious setting combinations or recommended starting
  configurations.

---

### docs/usage.md

**Purpose:** Shows a new user how to accomplish their first real task with the plugin.
Bridges the gap between "installed" and "producing value".

**Suggested section structure:**

- H2 `## First use` — minimal walkthrough: open Obsidian, trigger the plugin's primary
  action, see the expected result.
- H2 `## Common workflows` — 2–4 named patterns a typical user will repeat
  (e.g. "Archive a note", "Search across vaults").
- H2 `## Tips and shortcuts` — keyboard shortcuts, context-menu entries, ribbon actions.
- H2 `## Examples` — optional; screenshots or animated GIFs for non-obvious interactions.

---

### docs/troubleshooting.md

**Purpose:** Helps a user recover from the most common failure modes without reaching
the plugin author. Written from the user's symptom, not the author's debugging model.

**Suggested section structure:**

- H2 `## Common issues` — one H3 per issue: symptom as heading, cause, fix steps.
  At minimum: "Plugin not appearing", "Command not found in palette", "Settings reset
  on restart".
- H2 `## Debug information` — how to open the developer console; what to paste when
  filing a bug report.
- H2 `## Getting help` — where to file issues (GitHub Issues URL), what information to
  include, expected response time.

---

### docs/settings-reference.md

**Purpose:** Comprehensive reference for every exposed setting, mirroring
`configuration.md` but with deeper context: allowed values, interaction with other
settings, and practical advice per option. Authored by hand; not auto-generated.

**Suggested section structure:**

- One H2 per logical settings group (e.g. `## Appearance`, `## Sync`, `## Advanced`).
- Within each group, one H3 per setting: name, allowed values table, default, effect,
  and a "when to change this" note.

---

### docs/commands-reference.md

**Purpose:** Lists every command the plugin contributes to the Obsidian command palette,
with a one-sentence description of what each command does and any preconditions.

**Suggested section structure:**

- H2 `## Commands` — Markdown table: `Command name | Description | Preconditions |
  Default hotkey`.
- H2 `## Notes` — optional; ordering or conflict notes if two commands share similar
  names.
