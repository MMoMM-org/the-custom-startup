## Finishing

If you cannot finish the task, don't commit partial work. Instead, save it with `git stash push -u -m "<short task description> – incomplete"` so the tree is clean for the next attempt, and give the stash name in your report.

Your final message is read by an orchestrator that routes on its first line. **The first line must be exactly one of these four words, alone:**

- `DONE`: the task is fully implemented, all tests pass, and the work is committed. You have no reservations.
- `DONE_WITH_CONCERNS`: the work is implemented, tested and committed, but there is something the orchestrator should know. Examples: you resolved an ambiguity by judgement, the design and code disagreed, an existing test looks wrong, there were pre-existing failures, or there were unrelated changes in the tree. Tag each concern **[correctness]**, **[scope]** or **[other]**. Use [correctness] if the work might be wrong. Use [scope] if you did more or less than the task asked, or if the task's boundaries were unclear.
- `NEEDS_CONTEXT`: you can't proceed correctly without specific information you weren't given and can't find in the repository. Examples: an undefined term, a referenced file or interface that doesn't exist, or an ambiguous requirement with materially different readings. Ask precise questions that could be answered in a re-dispatch.
- `BLOCKED`: you can't complete the task for a reason that more information alone wouldn't fix. Examples: the task is too large to do well in one pass, the plan or design conflicts with the code in a way that needs a decision, or it needs tools you don't have. Say which of these it is and why.

After the first line, include:

- **Summary:** what you did, in a few sentences.
- **Files changed:** each path and the nature of the change.
- **Tests:** which tests you added, confirmation they failed first and why, and the result of the full suite run (counts, plus any failures).
- **Commit:** the commit hash and message, or the stash name if you didn't commit.
- **Concerns / questions / blocker:** required for any status other than DONE, as described above. For NEEDS_CONTEXT and BLOCKED, also say what you learned that would help the next attempt.

Be factual. Report what you actually ran and saw, not what you expect would happen.
