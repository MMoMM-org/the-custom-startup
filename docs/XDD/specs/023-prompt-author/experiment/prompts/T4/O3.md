# ledgerlite

Small, stdlib-only Python package that turns CSV ledgers into plain-text EUR totals. There are no third-party dependencies and no packaging config. Don't add either without asking.

## Commands

Run everything through `scripts/dev.sh`. It `cd`s to the repo root itself.

- `./scripts/dev.sh test [unittest args]` runs the test suite.
  - It sets `LEDGERLITE_HOME=tests/fixtures`. Without that, `tests/test_report.py` fails at import and the CLI tests fail. The README's bare `python3 -m unittest` only works if you export `LEDGERLITE_HOME` yourself.
  - It writes the exit status to `.dev-test-stamp`, which is gitignored. Leave that file alone.
  - To run a single test: `./scripts/dev.sh test -k test_totals_by_month`.
- `./scripts/dev.sh lint` runs the style check over `ledgerlite tests scripts`, then `gen_rates.py --check`. Run it before declaring work done.
- `./scripts/dev.sh fmt` only fixes trailing whitespace and the final newline. You must fix long lines (over 99 chars) and tab characters by hand. The linter only looks at `.py` and `.sh` files.
- `./scripts/dev.sh gen` regenerates the rates module.

## Exchange rates

`ledgerlite/_rates.py` is generated from `data/rates.csv` and must not be edited by hand. The README says rates "are in" `_rates.py`, which is misleading.

To change rates, edit `data/rates.csv` and then run `./scripts/dev.sh gen`. The `--check` step in lint compares the exact rendered text, including the sha256 of the CSV bytes. Any edit to the CSV, even whitespace, needs a regen.

Tests hardcode the current rates. `tests/test_currency.py` assumes GBP 1.25 and USD 0.875, and the totals in `tests/test_report.py` derive from them. A rate change means updating those expectations too.

## Test fixtures

`tests/fixtures/ledger.csv` is both the default ledger for the CLI tests (via `LEDGERLITE_HOME`) and the input to the exact totals asserted in `test_report.py`. Those asserts include a table total of `161.00` and exact float `assertEqual` on the totals.

If you edit the fixture, recompute those expectations. For new cases, prefer inline CSV strings, as `test_parser.py` does.

## Behaviour to preserve (or change only deliberately, with tests)

- **Thousands separators.** `parser._parse_amount` strips every comma, so `"1,234.50"` becomes 1234.5. A European decimal comma such as `"12,50"` therefore parses as 1250.
- **Currency codes.** Codes are upper-cased by the parser and again by `currency.convert`.
- **Unknown currencies.** An unknown code raises `UnknownCurrency`, which is a `KeyError`.
- **Missing category.** An empty category becomes `"uncategorized"`.
- **Blank rows.** All-blank rows are skipped, but they still count for line numbering. `ParseError.line` is the 1-based file line, and the header is line 1.
- **Amount formatting.** `report.format_amount` truncates cents rather than rounding, and float error can drop a cent. If you touch it, add tests for the edge cases.
- **Table sorting.** `format_table` sorts by total descending, then by key, and appends a `total` row.

## Adding a grouping

Add the key logic to `report._group_key`. Also add the choice to `--by` in `cli.build_parser`; argparse rejects anything not listed there. Add tests in `test_report.py` and `test_cli.py`.

## Conventions

- Keep using `str.format`-style code and stdlib `unittest`, matching the existing code.
- The version lives in `ledgerlite/__init__.py` (`__version__`). Only bump it when asked.
