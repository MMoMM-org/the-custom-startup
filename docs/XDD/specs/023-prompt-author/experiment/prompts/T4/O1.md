# ledgerlite

A small, stdlib-only Python package. It parses ledger CSVs and prints per-category or per-month totals converted to EUR. There are no third-party dependencies, so don't add any. Tests use `unittest`, not pytest.

## Commands

Run everything through `./scripts/dev.sh` from any directory, because it `cd`s to the repo root itself:

- `./scripts/dev.sh test` runs the full test suite. Extra args go to `unittest discover`, e.g. `./scripts/dev.sh test -k format_amount`.
- `./scripts/dev.sh lint` runs the style check over `ledgerlite`, `tests` and `scripts`, plus the rate-table freshness check.
- `./scripts/dev.sh fmt` auto-fixes trailing whitespace and final newlines only.
- `./scripts/dev.sh gen` regenerates `ledgerlite/_rates.py` from `data/rates.csv`.

Before calling a change done, run both `test` and `lint` and report the actual output.

**Don't run plain `python3 -m unittest`**, even though the README suggests it. `tests/test_report.py` calls `config.home()` at import time, so the run fails with `RuntimeError: LEDGERLITE_HOME is not set` unless that variable points at `tests/fixtures`. `dev.sh test` sets it for you. If you must call unittest directly, run `LEDGERLITE_HOME=$PWD/tests/fixtures python3 -m unittest discover -s tests -t .`.

`dev.sh test` writes the exit status to `.dev-test-stamp`. That file is gitignored, so don't commit it or delete it.

To try the CLI by hand, run `LEDGERLITE_HOME=$PWD/tests/fixtures python3 -m ledgerlite.cli report --by month`, or pass a CSV path explicitly.

## Exchange rates

- `ledgerlite/_rates.py` is generated, so never edit it by hand. The README says rates live there, but the source of truth is `data/rates.csv`.
- To change a rate, edit `data/rates.csv` and then run `./scripts/dev.sh gen`.
- `lint` fails if the generated file doesn't exactly match what the generator would produce. The generated file embeds a sha256 of the CSV, so even a whitespace change to the CSV requires regenerating.
- The tests hard-code the current rates: GBP 1.25 and USD 0.875 in `test_currency.py`, and the totals in `test_report.py`, which are derived from `tests/fixtures/ledger.csv`. If you change those rates or that fixture, update the expected values deliberately rather than loosening the assertions.

## Code layout

- `parser.py` turns CSV text into `model.Transaction`, a frozen dataclass.
  - Required columns are `date,amount,currency,category`; `description` is optional.
  - Dates are ISO only.
  - Commas in amounts are stripped as thousands separators, so decimal-comma amounts like `12,50` parse as `1250`.
  - Currency is uppercased. An empty category becomes `uncategorized`. Fully blank rows are skipped.
  - `ParseError.line` is the 1-based file line, with the header at line 1. Keep that contract when you touch the parser, because the tests assert it.
- `currency.py` handles conversion via `EUR_PER_UNIT`. Unknown codes raise `UnknownCurrency`, a `KeyError` subclass. The parser doesn't validate currencies, so this error surfaces at report time.
- `report.py` does the grouping and table rendering.
  - Tables sort by total descending, then by name.
  - `format_amount` truncates cents rather than rounding. Changing that changes CLI output, so add tests if you do.
- `cli.py` contains `main(argv, out)`. It takes an output stream so tests can capture output. Keep new subcommands testable the same way.
- `config.py` holds the `LEDGERLITE_HOME` lookup. It is the only place that reads the environment.

## Style

`scripts/lint.py` enforces a 99-character maximum line length, no tabs, no trailing whitespace, and a final newline, across `.py` and `.sh` files. `fmt` won't fix long lines or tabs, so wrap those yourself. Match the existing style: `str.format` rather than f-strings, and module docstrings at the top of each file.

The version lives in `ledgerlite/__init__.py`. Don't bump it unless asked.
