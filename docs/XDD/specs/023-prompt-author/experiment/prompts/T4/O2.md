# ledgerlite

A small, stdlib-only Python 3 tool that reads ledger CSVs and prints per-group totals converted to EUR. There are no third-party dependencies and nothing to install. Run all commands from the repo root.

## Commands

- **Tests:** `./scripts/dev.sh test`
  - Use this rather than the README's bare `python3 -m unittest`.
  - The test modules call `config.home()`, which raises `RuntimeError` unless `LEDGERLITE_HOME` is set. `dev.sh test` sets it to `tests/fixtures`.
  - Arguments are passed through to `unittest discover`. For example, `./scripts/dev.sh test -k format_amount`.
  - To run a single module: `LEDGERLITE_HOME=$PWD/tests/fixtures python3 -m unittest tests.test_parser`.
- **Lint:** `./scripts/dev.sh lint`
  - Checks `.py` and `.sh` files in `ledgerlite/`, `tests/` and `scripts/`.
  - Rules: lines of at most 99 characters, no tabs, no trailing whitespace, and a final newline.
  - It also fails if `ledgerlite/_rates.py` is stale.
- **Format:** `./scripts/dev.sh fmt`
  - This only fixes trailing whitespace and final newlines. You must fix long lines and tabs by hand.
- **Regenerate rates:** `./scripts/dev.sh gen`

Before you say a change is done, run both `test` and `lint` and report the results.

## Exchange rates

- `ledgerlite/_rates.py` is generated. Never edit it by hand, even though the README points there.
- To change rates, edit `data/rates.csv`, then run `./scripts/dev.sh gen`.
- The generated file stores a SHA-256 of the CSV's raw bytes. Any edit to the CSV, including whitespace, makes `lint` fail until you regenerate. Commit both files together.
- The tests hard-code the current rates (GBP 1.25, USD 0.875) and the totals derived from them. If you change a rate, update `tests/test_currency.py` and `tests/test_report.py` as well.

## Tests and fixtures

- `tests/fixtures/ledger.csv` is the default ledger for the CLI tests and the data behind the exact totals in `test_report.py`. These include category and month sums, sort order, and the `161.00` grand total.
- If you add rows to that file, every one of those expectations changes. For new parser or report cases, prefer inline CSV strings, the way `test_parser.py` does it.
- `totals_by` results are compared with exact `assertEqual` on floats. That only works because the current values are binary-friendly. Use `assertAlmostEqual` for new cases with arbitrary amounts.

## Code notes

- **Flow:** `cli.py` → `parser.parse_file` → `model.Transaction` → `report.totals_by` (which uses `currency.to_eur`) → `report.format_table`.
- **`cli.main(argv, out)`:** keep this signature. The tests inject `out` and check the return code.
- **`parser`:**
  - Upper-cases currency codes.
  - Strips `,` thousands separators from amounts.
  - Skips all-blank rows.
  - Maps an empty category to `uncategorized`.
  - Raises `ParseError` with the 1-based CSV line number, where the header is line 1.
  - Unknown currencies are not checked at parse time. They raise `currency.UnknownCurrency` during reporting.
- **`report.format_amount`:** truncates cents rather than rounding, so float error can show up (0.29 → "0.28"). Treat any change here as a deliberate output change and add tests for it.
- **Version:** lives in `ledgerlite/__init__.py`.
- **`.dev-test-stamp`:** written by `dev.sh test` and gitignored. Don't commit it.
